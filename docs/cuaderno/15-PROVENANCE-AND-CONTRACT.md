# Procedencia y permiso contractual comunicado

El propietario del proyecto declara haber obtenido permiso en contratos separados. Esta es una premisa del plan, no una auditoría jurídica. No se solicita de nuevo el documento ni se usa la licencia pública como motivo para cambiar de Tandoor a Grocy.

Para cada pieza adaptada registrar repo/SHA/rutas, naturaleza de reutilización, tests portados, cambios y avisos que se conservan. Referencia interna al contrato cuando el propietario la facilite, sin texto confidencial. No afirmar que el autor de un proyecto otorgó permisos de terceros que no conocemos.

Conservar LICENSE/NOTICE y atribución salvo instrucciones contractuales específicas revisadas por el propietario. No publicar secretos/recetas; no declarar como código completamente original una base heredada. Branding profesional no exige ocultar la procedencia del código.

Un fragmento genérico reimplementado a partir de una especificación sigue registrando la referencia técnica. Esto facilita mantener el producto al actualizar y distinguir contribuciones propias de upstream. No bloquea trabajar.
